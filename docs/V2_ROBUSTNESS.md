# UPGRADE-BENCH v2 robustness protocol

> **Public reviewer-release status:** the current-registry corrected schema-2 robustness JSON/CSV is
> included as a receipt-bound descriptive diagnostic. Maintainer verification covers 504 metric
> rows, all 24 candidate hashes, the raw archive, and 18 rolling choices frozen before main/raw
> access. The raw archive remains private, so the public release carries the sanitized result pair
> and its hash bindings rather than claiming public reconstruction of the private-provenance check.

This document fixes the robustness suite generated by
`tools/v2_robustness.py`. The suite is independent of the GPU runner and never
uses a main-window metric to choose a model, hyperparameter, or reported
champion.

The formal external-pretrained ULTRA-ZS reference is outside this robustness suite: it does not
select a checkpoint from these slices and no robustness result is used to tune or calibrate it. A
release must separately verify the 6/6 chain-score seal, all 18 chain--task records, the
sheep repeat, and the sanitized pair. The current receipt-authorized sanitized pair is included in
the public reviewer release.
ULTRA-ZS uses target early graphs and unmatched external pretraining resources, so its comparisons
are descriptive rather than graph-free-cold-start, fair-compute, champion, significance,
population, or causal claims.

The formal GBDT reference is also outside this robustness suite. Its four-point grid is selected
only on grouped historical folds, all 18 models are frozen before main access, and its 200-draw
cluster intervals are computed on the single frozen main cohort. No robustness slice chooses its
configuration or calibrates its scores. Numerical values must come from a receipt-bound current
interface; the current verified JSON/CSV pair is included in the public reviewer release. The GBDT
reference is not a robustness-selected champion.

## Frozen systems and temporal boundary

For each of the six chains, the three historical logistic systems use the
regularization value selected previously on the `1998-2002 -> 2008-2012`
fold. The values are read only from `--rolling-result`; there is no hard-coded
choice table or silent fallback in the robustness runner. Before parsing any
candidate CSV or raw late-window label, the runner calls
`v2_rolling_cpu_baselines.verify_existing_output`, requires the current rolling
schema and all anti-leakage flags, checks exactly six chains and 24 current
candidate-input hashes, and validates the complete grouped-CV trace for each of
the 18 chain/task choices. The recorded `selected_C` must be the deterministic
historical winner, including the smaller-C tie break. Missing, extra,
nonhistorical, stale, or internally inconsistent choice records abort the run.

The verifier hashes all 24 input files without parsing their columns or labels.
Only after that gate are the 18 choices frozen, and only then are the fold2
tables parsed to fit the systems. Raw size, capacity, demand, and gravity
rankings are retained as protocol-fixed comparators. All systems are fitted and
frozen for all chains before any main table or raw late-window label is opened.

## Protocol-fixed diagnostics

| family | exact definition | interpretation |
|---|---|---|
| exporter identity | seen iff the exporter occurs in the corresponding fold2 candidate table | `exporter_unseen` is the exporter-disjoint sensitivity |
| importer identity | seen iff the importer occurs in the corresponding fold2 candidate table | `importer_unseen` is reported for A and B2; B1 has no importer unit |
| hub exclusion | remove rows involving `BEL,CHE,HKG,NLD,PAN,SGP,ARE`; B1 removes those exporters | merchant/re-export sensitivity |
| reporting-entity exclusion | likewise remove `ANT,CSK,DDR,SCG,SUN,YUG` | dissolved/reporting-entity hygiene sensitivity |
| threshold | raw late calendar mean strictly greater than 50, 100, or 250 kUSD | outcome-only relabeling; candidate eligibility stays at the shipped 100-kUSD rule |
| persistence | raw annual stage total strictly greater than 100 kUSD in at least 3 of 5 years | auxiliary strict label; not the benchmark default |

Threshold results are deliberately named `threshold_outcome_only`. They are not
alternate benchmark cohorts because early-window candidate eligibility is not
rebuilt at 50 or 250 kUSD. This prevents an outcome relabeling from being
mistaken for a full threshold-specific universe reconstruction.

Persistence is rebuilt from the raw BACI archive. For every candidate lane, HS6
values are first summed to a stage total separately in each of 2018--2022.
Missing lane-years are zeros. `active_years_100kusd` counts the years whose
annual stage total is strictly above 100 kUSD; it is never inferred from the
five-year mean or from the shipped `lateval` field. The default 100-kUSD
calendar-mean labels must reconcile before any sensitivity result is written.
The reported persistence rule is the literal active-year criterion and is not
conjoined with `late_mean > 100`; it is therefore not guaranteed to be a subset
of the default positives. A conjunctive "default positive and persistent"
definition would be a separate, currently unreported sensitivity.

## Metrics and uncertainty

Track A and B1 report average precision with exporter-cluster bootstrap
intervals. Track B2 reports conditional recall/value capture at `k={1,3,5}`
with exporter-stage entry bootstrap intervals. For a filtered B2 slice, ranking
is conditioned on entries with at least one positive destination after applying
that exact slice and auxiliary label; dropped zero-positive groups are counted
in the output.

## Reproduction and stale checks

```powershell
& '.\.venv\Scripts\python.exe' tools\v2_robustness.py `
  --rolling-result results_v2\metrics\rolling_cpu_baselines.json
& '.\.venv\Scripts\python.exe' tools\v2_robustness.py --verify-output
```

The JSON records the command, environment, frozen choices, all 24 candidate
input hashes, raw BACI hash, exact rolling-artifact hash, canonical choice
digest, generator/helper hashes, and CSV hash. Output verification reruns the
rolling verifier and requires the stored choice matrix and hashes to match the
current rolling artifact. Any mismatch is rejected rather than silently
accepting a stale result.
